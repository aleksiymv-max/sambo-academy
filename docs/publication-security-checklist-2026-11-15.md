# Предпубликационная проверка безопасности Sambo Academy

**Статус: BLOCKED.** Текущий приватный репозиторий нельзя безопасно переводить в Public только удалением файлов из main.

## Подтверждённые наблюдения (15.11.2026)

- main на момент проверки: 526720369d40180599870049252bacfe6ea8f53a.
- В истории main обнаружено **563 коммита** с незамаскированным Gmail-адресом автора. Не копировать полный адрес в документы и журналы.
- Обнаружено **105 веток**, включая main. При публикации история опубликованных веток и PR может раскрывать прежние метаданные.
- В текстовых файлах текущего main сканирование типовых email/телефонов/секретов не выявило выгрузок реальных пользователей. Это не гарантирует отсутствие нестандартных персональных сведений или сведений в старых коммитах, PR и бинарных файлах.
- Пять изображений: ручная проверка всех лиц, метаданных EXIF/GPS, согласий и прав ещё не завершена. Использование символики Федерации требует подтверждения разрешения.
- Клиентский ключ sb_publishable_ в auth-config.js публичный; **service_role, секретные API-ключи и пароли нельзя добавлять в браузерный код**.
- supabase/guardian_applications.sql содержит схему для персональных данных несовершеннолетних и представителей; supabase/lesson_progress.sql — учебного прогресса. Это **схемы**, а не выгрузки базы. RLS в SQL не доказывает, что политики действительно применены к действующей БД.
- privacy.html обозначает текст политики как неутверждённый. Оператор, сроки хранения, согласия и вопросы трансграничной передачи требуют проверки.

## Технические меры

- .gitignore исключает типовые локальные секреты, дампы, списки пользователей и артефакты.
- scripts/check-repo-privacy.cjs проверяет отслеживаемые текстовые файлы на распространённые токены, приватные имена файлов, email и российские мобильные номера. Совпадения выводятся **без самих значений**.
- Validate Sambo Academy запускает self-test сканера и проверку текстовых файлов на каждом PR/push.
- Ручной workflow Public release privacy preflight проверяет исторические email автора и коммитера всех доступных ссылок Git (fetch-depth: 0). Пока Gmail-история остаётся, он должен завершаться с ошибкой — **это реальный блокер**, не сбой CI.
- Автопроверка не заменяет ревизию изображений, реальных баз, прав, старых файлов, PR и внешних копий.

## Обязательные действия перед Public

1. **Не переключать текущий repo в Public.** Самый безопасный путь — новый репозиторий с чистой начальной историей из проверенного состояния, при сохранении старого приватным. Не переносить скрытые старые ветки/теги/PR.
2. В [настройках почты GitHub](https://github.com/settings/emails) включить защиту email, для новых коммитов использовать noreply-адрес. Это **не исправляет старую историю**.
3. Для сохранения старого URL нужен отдельный проверенный план переписывания истории и всех веток/тегов/PR, GitHub caches и копий. Нельзя выполнять массовый force-push без резервной копии и контроля CI.
4. Пересмотреть **каждое** изображение, EXIF/GPS, лицензии, разрешения на публикацию узнаваемых людей и символики. Не переносить спорные файлы в публичную сборку.
5. Проверить реальные политики Supabase RLS (несовершеннолетние, представители, прогресс), доступность Storage и защиту от чтения чужого user_id. Не публиковать реальные записи, дампы, снимки личных кабинетов.
6. Проверить Actions secrets/variables, Cloudflare и Supabase; перевыпустить ранее утекшие секреты, если они были. Ключ sb_publishable публичный, сервисные роли — нет.
7. Утвердить политику и согласия с фактическим оператором персональных данных до полноценного сбора информации.
8. Выполнить сканер в режимах --self-test, обычном и --history; документировать результаты, дополнительно вручную проверить исторические файлы и assets.
9. Перед переключением Public проверить авторизацию, серверные ограничения, сохранение прогресса и актуальную production-сборку. Сканер **не заменяет** E2E.

**Не объявлять репозиторий безопасным для Public**, пока остаётся хотя бы один пункт, в особенности Gmail-история, отдельные ветки и непроверенные изображения.
