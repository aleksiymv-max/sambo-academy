# Поштучная матрица доказательств судейского курса

Дата начала: 02.11.2026. **Это не акт приёмки и не подтверждение нормативной готовности.**

## Как получать фактический перечень

`node scripts/check-judge-evidence-ledger.cjs` читает **активные** модули, уроки и экзаменационные банки из текущего checkout и создаёт `judge-review-inventory.json`. В GitHub Actions файл публикуется как временный артефакт `judge-review-inventory`. Число уроков и заданий вычисляется, а не переносится из прежних отчётов.

Каждая запись содержит служебный адрес вида `judge-module-04/lesson-02` или `judge-module-04/exam-003`, название/ссылку на статью (для урока), SHA-256 содержания и статус. **Это идентификаторы аудита, а не ID пользовательского прогресса.** Переименование, перестановка или изменение вопроса требует новой сверки; ни один индекс прогресса, ключ или версия экзамена скриптом не меняется.

## Когда можно записать подтверждение

В `docs/judge-evidence-approvals.json` вручную добавляют запись по служебному адресу только после проверки по оригинальному тексту сводных Правил (приказ № 892, изменения по № 860 от 14.09.2026) и отдельным актуальным официальным поправкам. Пример формата (не реальное одобрение):

```json
{
  "content_sha256": "SHA-256 ИЗ АКТУАЛЬНОГО ИНВЕНТАРЯ",
  "source_url": "URL конкретного официального источника",
  "evidence_url": "ссылка на протокол редакторской сверки",
  "reviewed_by": "идентификатор фактического редактора",
  "reviewed_at": "2026-11-02",
  "criteria": {
    "sequence": true,
    "normative": true,
    "pedagogy": true,
    "case": true,
    "assessment": true,
    "accessibility": true,
    "compatibility": true
  }
}
```

Для экзамена критерии: `normative`, `distractors`, `independent`, `explanation`, `accessibility`. Поля `source_url`, `evidence_url`, `reviewed_by`, `reviewed_at` обязательны. Неполная запись не считается принятой. При изменении содержания прежний SHA-256 перестаёт совпадать и статус становится `stale_content_hash`. Заполнение всех полей — необходимое, но не достаточное условие: реальное экспертное заключение, браузерный E2E и публикация проверяются отдельно.

**Никогда не заполнять статусы автоматически на основании прохождения CI.** Нельзя использовать «100%» как оценку качества, пока нет доказательств по каждому уроку, вопросу, статье, приложению, дисциплине и интерфейсу. Известные разночтения по статьям 33, 35, 38, 40–41, 45/56, 66/68 и отдельным изменениям 2026 года остаются открытыми до официального уточнения.

## Технические ограничения

Проверка точного совпадения текста вопроса и самопроверки выявляет только дословные дубли. Смысловые повторы и некорректные ключи требуют ручной экспертизы. Доказательства не подменяют независимого практикующего судью. Временный JSON не содержит пользовательских результатов и не влияет на доступ к платным урокам.
