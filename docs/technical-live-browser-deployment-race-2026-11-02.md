# CI: живой браузер до проверки версии Cloudflare — 02.11.2026

## Наблюдение

После объединения [PR #85](https://github.com/aleksiymv-max/sambo-academy/pull/85) в `main` (`8b24041793fda5732a6d2789683c0be63745e0b4`) workflow [Validate Sambo Academy](https://github.com/aleksiymv-max/sambo-academy/actions/runs/41474299342) прошёл. [Browser and deployment smoke tests](https://github.com/aleksiymv-max/sambo-academy/actions/runs/41474299391) завершился **failure**: 187/194 проверок, семь ошибок в LIVE-секции. Живой браузер увидел 8 модулей вместо 12 и не нашёл `.judge-prime h2`; отдельные запросы к JS-ресурсам возвращали 200. Это **не успешный E2E** и не доказательство исправности опубликованной версии.

Непосредственная причина несоответствия (устаревший HTML/кеш, задержка публикации или другой сбой) не установлена окончательно. Однако порядок шагов был объективно неверным: LIVE браузер запускался **до** строгой проверки SHA-совпадения 21 файла. При ошибке браузера проверка публикации вообще не запускалась.

## Исправление проверочного контура

- На `main` проверка `check-deployment-parity.mjs` теперь выполняется **до** браузера; PR продолжает локальные браузерные тесты без требований к публикации незамёрженной ветки.
- Проверка сравнивает **байты** 21 опубликованного файла с checkout и не выдаёт PASS для старого или недоступного файла. Окно ожидания ограничено 30 попытками по 5 секунд вместо 15; превышение по-прежнему завершает CI ошибкой.
- После подтверждения полного совпадения запускаются браузерные тесты живого сайта. При новом несоответствии остаётся видимый FAIL, а не автоматическое признание сайта готовым.

## Границы

Перестановка шагов не исправляет возможную реальную ошибку сайта и не заменяет тест регистрации/повторного входа с реальным аккаунтом. Требуется успешный `Validate`, `Browser and deployment smoke tests` на итоговом `main` и отдельная экспертная нормативная приёмка. Не менялись уроки, экзамены, ключи, прогресс, платный доступ.
